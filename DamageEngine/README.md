# Damage Engine & Balance Harness

**프로젝트**: GunRogue (개인 프로젝트 — 총기 조합 로그라이크)
**역할**: 설계 및 전체 구현

데미지 공식 엔진과, 그 수치를 **Unity 없이 자동 검증**하는 콘솔 도구 2종입니다.

밸런스를 감각이 아니라 계측으로 잡기 위해 만들었습니다. 엔진을 `UnityEngine` 비의존으로 작성한 덕분에 런타임·에디터 툴·콘솔 하네스 세 곳이 **같은 코드**를 공유합니다.

---

## 설계 목표

- 데미지 공식을 Unity에서 분리해 콘솔에서 즉시 검증 가능하게 만들기
- 수치 변경 시 회귀를 자동으로 잡아내기
- 사람이 못 짜는 조합 공간을 탐색해 밸런스 사각을 찾기
- 도구가 참조하는 수치와 실제 게임 수치의 드리프트 제거

---

## 1. 데미지 공식 엔진 — `DamageCalculator`

2층 파이프라인으로 구성됩니다.

```
층1  탄당_물리 = (기본 + 가산) × (1 + Σ증가%) × Π(1 + 승산%) × 크리보정
층2  총 데미지 = 탄당 × 총 탄 수 × 다중표적 보정
```

**순서 의존**이 핵심입니다. 가산을 모두 합산 → 증가%는 전부 더해 **1회** 곱 → 승산%는 **각각** 누적 곱 → 크리 순으로 고정되어 있으며, 이 순서가 바뀌면 결과가 달라집니다.

`BuildStats` 구조체가 모드 집계 결과를 스칼라로 보관해 GC 할당 없이 전달합니다. 물리 축과 속성 축(화염/독/감전)이 동형 구조(`Flat` / `IncreasedPercent` / `MoreMultiplier`)로 설계되어 있어 축을 추가해도 계산부는 변하지 않습니다.

> **설계 의도**: `UnityEngine` 참조를 넣지 않은 것이 이 시스템 전체의 전제입니다. 참조가 하나라도 들어가면 콘솔 검증이 불가능해지고, 검증 도구가 공식을 따로 구현하게 되어 원본과 어긋납니다.

## 2. 회귀 검증 하네스 — `DamageHarness.Program.cs`

```bash
dotnet run --project Tools/DamageHarness
```

Unity를 켜지 않고 콘솔에서 실행되는 검증 스위트입니다. **Assert 395건 / 시나리오 24종**으로 데미지·경제·상점·스테이지·보스·상태이상·조건부 모드를 검사합니다.

| 시나리오 예 | 검사 내용 |
|-------------|-----------|
| `GrowthCurve` | 가산 vs 승산 성장 곡선 차수 비교 |
| `EconomyScenario` | 재화 수급과 요구치 곡선의 정합 |
| `BossRampScenario` | 스테이지별 보스 강도 램프 |
| `TargetModelScenario` | 표적 편성 모델(필드 수·처치 비율) |
| `StatusPipelineScenario` | 화상·중독 부여량과 틱 누적 |

**기대값을 상수로 박지 않는 것**이 이 하네스의 규칙입니다. 기대값은 `GameConfig`의 밸런스 상수에서 파생시켜, 상수를 바꾸면 기대값이 자동으로 따라옵니다.

> **실제 사례**: 기본 크리율을 0 → 0.10으로 올린 커밋에서 이 규칙을 어기고 숫자를 직접 박아둔 케이스 95건이 조용히 죽어 있었습니다. 이후 전 기대값을 헬퍼 함수(`Crit()` / `P()`) 경유로 강제해 같은 사고를 구조적으로 막았습니다.

### 하네스가 잡아낸 결함

크리 기댓값 계산에 상한 클램프가 없었습니다. 실제 전투는 `rng < 크리율` 확률 롤이라 100% 초과분이 버려지는데, 기댓값 공식은 그대로 곱하고 있었습니다.

- 크리율 140%(실제 조합 가능) · 배율 3.0 기준
- 통계 3.80배 **vs** 실전투 3.00배 → **27% 과대평가**

세 도구(런타임 통계 / DamageLab / 하네스)가 이 함수 하나를 공유했기 때문에 **셋이 함께 틀렸고**, 셋 다 정상으로 보였습니다. 한 줄 클램프로 동시에 교정했습니다.

> 코드 공유는 일관성을 보장하지만, 공유 지점이 틀리면 검증 수단까지 같이 틀린다는 점을 확인한 사례입니다.

## 3. 조합 탐색 랩 — `ComboLab.Program.cs`

```bash
dotnet run --project Tools/ComboLab -- [--beam N] [--top N] [--gun 소총]
```

모드·탄약 조합 중 상위 데미지 빌드를 찾아, 모드를 상위/하위 그룹으로 분류합니다.

**전수 탐색이 불가능**합니다 — 소총 하나만 해도 `C(17,6) × C(35,4) ≈ 6.5억` 조합에 시퀀스 순열이 곱해집니다. 그래서 시퀀스 아키타입을 고정하고 슬롯을 하나씩 채우는 **빔 서치**로 상위 빌드를 수집합니다.

> **설계 의도**: 빔 폭 안에서 곱연쇄와 조건 충족이 함께 살아남기 때문에, "혼자서는 약한데 셋이 모이면 강한" 조합도 잡힙니다. 그리디로는 이런 조합이 1단계에서 탈락합니다.

수치는 하드코딩하지 않고 **`.asset`(YAML)을 직접 파싱**합니다. 밸런스 수치를 고치고 재실행하면 바로 반영되므로, 도구와 게임 수치가 어긋나는 드리프트가 발생하지 않습니다.

## 파일 구성

| 파일 | 설명 |
|------|------|
| `DamageCalculator.cs` | 데미지 공식 엔진 (순수 로직) |
| `BuildStats.cs` | 모드 집계 입력 구조체 — 물리/속성 동형 설계 |

| `DamageHarness.Program.cs` | 회귀 검증 하네스 (Assert 395건) |
| `ComboLab.Program.cs` | 빔 서치 조합 탐색 · `.asset` 직접 파싱 |
