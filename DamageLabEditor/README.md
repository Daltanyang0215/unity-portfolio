# Damage Lab (Editor Tool)

**프로젝트**: GunRogue (개인 프로젝트 — 총기 조합 로그라이크)
**역할**: 설계 및 전체 구현

밸런스 수치를 눈으로 보고 조정하기 위해 만든 `EditorWindow` 확장 도구입니다.

수치를 바꿀 때마다 빌드를 돌려 플레이로 확인하는 비용이 너무 커서, **에디터 안에서 즉시 결과를 보는 것**을 목표로 제작했습니다.

---

## 설계 목표

- 게임과 **동일한 수식**으로 그린다 — 툴이 공식을 따로 구현하지 않을 것
- 게임 코어를 수정하지 않을 것 (읽기 전용 사용)
- 빌드/플레이 없이 조합을 바꿔가며 즉시 비교
- 단일 케이스뿐 아니라 반복 시행 통계까지 산출

---

## 구성 — 3개 탭

| 탭 | 기능 |
|----|------|
| **분석 / 비교** | 프리셋 A/B를 조립해 탄별 데미지·누적 곡선을 그래프로 비교 |
| **시뮬레이션** | 인게임 루프(클리어 → 보상 → 상점 → 다음 스테이지)를 숫자판으로 재현 |
| **자동 (통계)** | AI 플레이 성향별로 N회 반복해 클리어율 통계 산출 |

윈도우 폭 900px을 기준으로 좌우 2단 / 상하 1단 레이아웃이 전환되는 반응형 셸로 구성했습니다.

---

## 핵심 설계

### 1. 코어 재사용 — `LabEngine`

툴은 공식을 자체 구현하지 않고 **게임의 순수 코어를 그대로 호출**합니다.

```
LabEngine.Build(preset, ...) → RunBuild 조립 → Walk(턴별 즉발 + 턴 종료 DoT) → LabSeries
```

> **설계 의도**: 툴이 공식을 복제하면 게임 수치가 바뀔 때마다 두 곳을 고쳐야 하고, 한쪽만 고치는 순간 툴의 출력이 거짓이 됩니다. 코어를 읽기 전용으로 호출하도록 고정해 이 문제를 원천 차단했습니다.

### 2. MonoBehaviour 로직의 에디터 재사용 — `LabSim`

상점 로직은 `ShopManager`(MonoBehaviour)에 들어 있어 에디터에서 직접 쓸 수 없었습니다.

- 숨김 `GameObject`로 `ShopManager`를 인스턴스화
- 상점 풀을 `SerializedObject`로 주입

이 방식으로 **게임 로직을 한 줄도 수정하지 않고** 에디터에서 상점 시뮬레이션을 돌립니다.

> **설계 의도**: 대안은 상점 로직을 순수 클래스로 분리하는 리팩터링이었지만, 툴 하나를 위해 검증된 런타임 코드를 건드리는 위험이 더 크다고 판단했습니다.

### 3. 그래프 렌더 — `LabGraph`

IMGUI + `Handles` 기반 커스텀 렌더입니다.

- **이중 Y축** — 좌: 탄당 순간 데미지 / 우: 누적 데미지
- 스택 막대(물리 / 속성 / DoT 칸) + 누적선 + 목표 요구치 점선 + **교차점 표시**
- 비교 모드: A/B 막대 닷지 배치 + B 누적선 오버레이
- 보너스 베이스라인 틱 — 조건부 효과가 얼마나 기여했는지 차분으로 표시
- 호버 툴팁

Pro/Light 스킨을 각각 대응해 어느 테마에서도 대비가 유지되도록 색상을 분기했습니다.

> 목표 요구치 점선과 누적선의 **교차점**이 이 그래프의 핵심입니다. "몇 번째 탄에서 스테이지를 넘는가"가 밸런스 판단의 기준이기 때문입니다.

### 4. 자동 통계 — `LabAuto`

AI가 대신 픽하는 런을 N회 반복해 통계를 냅니다. `LabSim`을 1런 엔진으로 재사용하고 **픽 정책만** 교체하는 구조입니다.

| 플레이 성향 | 픽 기준 |
|-------------|---------|
| `Greedy` | 즉시 데미지 최대 |
| `MoreStack` | 승산% 우선 누적 |
| `Volume` | 탄 수 축 우선 |
| `Elemental` | 속성 축 우선 |
| `Random` | 무작위 (바닥선) |

> **설계 의도**: 단일 최적 빌드만 보면 천장만 재게 됩니다. 무작위 픽을 바닥선으로 함께 돌려야 "못 짜도 넘어가는가"(데드엔드 방지)를 확인할 수 있습니다.
