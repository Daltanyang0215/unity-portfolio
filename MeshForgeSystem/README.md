# Mesh Forge System

**프로젝트**: Forest-Blacksmith (개인 프로젝트 — 대장간 제작 게임)
**역할**: 설계 및 전체 구현

망치질로 금속 주괴의 **메시를 실시간 변형**하고, 목표 형태와 얼마나 일치하는지 판정하는 시스템입니다.

미리 만든 완성품 메시로 교체하는 방식 대신, 플레이어의 타격이 실제 버텍스를 움직이고 그 결과를 형상 비교로 채점하는 구조를 목표로 했습니다.

> 프로토타입 검증 단계의 코드입니다. 형상 변형과 일치도 판정의 골격 검증이 목적이며, 온도 페널티 등 일부 규칙은 미적용 상태입니다.

---

## 설계 목표

- 타격이 메시에 직접 반영되는 촉각적 피드백
- 매 프레임 돌려도 감당 가능한 형상 비교 비용
- 변형 후에도 금속의 각진 실루엣(하드 엣지)이 유지될 것

---

## 전체 구조

```
AnvilInteraction (모루)
      ↓ ApplyHit(hitPoint, force)
IngotMeshItem
      ├─ 1단계: ApplyScaleForging   축 단위 스케일 변형
      └─ 2단계: ApplyDetailForging  타격 지점 버텍스 이동
                        ↓
              MeshComparer.HybridCompare
                        ↓
                  완성 판정 (임계 80%)
```

## 핵심 설계

### 1. 2단계 가공 모델 — `IngotMeshItem`

한 가지 변형 방식으로는 "덩어리를 두들겨 편다"와 "표면을 다듬는다"를 모두 표현할 수 없어 단계를 나눴습니다.

| 단계 | 방식 |
|------|------|
| **1단계 — 스케일 가공** | 타격 방향(위 벡터)과 가장 가까운 축을 점곱으로 찾아 그 축을 압축, 나머지 두 축을 **현재 비율대로 분배해 확장** |
| **2단계 — 세부 가공** | 타격 지점 반경 내 버텍스만 골라 목표 메시 방향으로 이동 |

1단계는 부피 보존 느낌을 내기 위해 줄어든 만큼을 나머지 축에 비율로 분배합니다. 변형 후에는 바닥 y 좌표를 재계산해 주괴가 모루에 떠 있거나 파묻히지 않도록 보정합니다.

주괴는 `Vector3` 최소 스케일로 하한을 두어, 계속 두들겨도 납작하게 소멸하지 않습니다.

### 2. 하이브리드 형상 비교 — `MeshComparer`

형상 일치도 판정이 이 시스템의 비용 병목입니다. 정밀 비교를 매 타격마다 돌리면 감당이 안 되고, 빠른 비교만 쓰면 정확도가 부족합니다. **2단계 조기 반환**으로 해결했습니다.

```csharp
public static float HybridCompare(Mesh a, Mesh b, float quickThreshold = 0.7f, int sampleCount = 200)
{
    float quickScore = QuickCompare(a, b);          // 1단계: Vertex-to-Vertex
    if (quickScore < quickThreshold)
        return quickScore;                          // 아직 한참 멀면 여기서 종료

    float preciseScore = CompareMeshesBySampling(a, b, sampleCount);  // 2단계: 표면 샘플링
    return (quickScore + preciseScore) * 0.5f;
}
```

| 단계 | 방식 | 비용 |
|------|------|------|
| `QuickCompare` | 버텍스 대 버텍스 직접 비교 | 낮음 |
| `CompareMeshesBySampling` | 두 메시 표면을 N개 지점 샘플링해 일치도 계산 | 높음 |

> **설계 의도**: 가공 과정의 **대부분 시간은 목표와 한참 떨어져 있는 구간**입니다. 이 구간에서는 정밀도가 필요 없고 "아직 멀었다"만 알면 되므로, 임계값(0.7) 아래면 빠른 비교 결과를 그대로 반환하고 끝냅니다. 완성이 임박한 구간에서만 정밀 비교가 켜지므로 평균 비용이 크게 떨어집니다.

### 3. 진행률 판정 — 최저 진행 축 기준

일치도를 전체 평균이 아니라 **가장 덜 진행된 버텍스 기준**으로 계산합니다.

```
목표 변화량  = target[i] - original[i]
현재 변화량  = working[i] - original[i]
진행 비율    = 현재 / 목표
반환값       = 모든 버텍스 중 최솟값
```

> **설계 의도**: 평균으로 재면 한쪽만 과하게 두들겨도 점수가 올라가 "덜 다듬은 부분이 남았는데 완성"이 됩니다. 최솟값 기준이면 모든 면을 고르게 다듬어야 완성되므로, 의도한 플레이(주괴를 돌려가며 전체를 가공)가 강제됩니다.

### 4. 하드 엣지 보존 — `MeshUtill.RecalculateHardNormals`

버텍스를 옮긴 뒤 Unity 기본 `RecalculateNormals()`를 쓰면 모든 면이 부드럽게 이어져 금속 특유의 각진 느낌이 사라집니다.

인접 면의 각도 차가 임계값(기본 60°) 이상이면 **버텍스를 분리해** 각 면이 독립 노멀을 유지하도록 재계산하는 확장 메서드를 작성했습니다.
