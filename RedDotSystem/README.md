# RedDot System

**프로젝트**: 여고생키우기 (ZTO Games)
**역할**: 설계 및 전체 구현

게임 내 알림 UI(RedDot)를 데이터 중심으로 관리하기 위해 제작한 트리 구조 기반 알림 관리 시스템입니다.

RedDot의 상태 관리와 UI 표시를 분리하여, 동일 알림의 다중 UI 노출 / 동적 콘텐츠 생성 / 콘텐츠 Unlock 상태에 따른 알림 지연 처리 문제를 해결하도록 설계했습니다.

최하위 RedDot의 상태 변경만으로 부모 노드까지 알림 상태가 자동 전파되며, Manager는 UI를 직접 참조하지 않는 이벤트 기반 구조로 구성되어 UI 변경 및 확장에 영향을 최소화하도록 구현했습니다.

---

## 설계 목표

- UI 구조와 RedDot 상태 로직 분리
- 동일 ID RedDot 다중 UI 대응
- 콘텐츠 미해금 상태에서의 알림 오표시 방지
- 데이터 변경 최소화로 상위 알림 자동 갱신
- 동적 콘텐츠에도 대응 가능한 구조

---

## 전체 구조

```
[Game Event]
      ↓
RedDotManager (데이터 관리)
      ↓ Event
RedDot (UI Component)
```

RedDotManager는 RedDot의 실제 위치나 개수를 알지 않으며, 데이터 상태만 관리합니다.
UI는 이벤트를 통해 자신의 상태만 갱신합니다.

---

## 구성 요소

### 1. RedDot (UI Component)

UI에 부착되는 컴포넌트로, 고유 RedDot ID를 가집니다.
직접 상태를 변경하지 않고, Manager 이벤트를 구독하여 표시 상태만 갱신합니다.

> **설계 의도**: 동일 ID의 RedDot이 여러 UI에 존재할 수 있기 때문에 Manager가 UI 참조를 직접 관리하지 않도록 구성했습니다.

### 2. RedDotData (데이터 모델)

RedDot의 상태 정보를 저장하는 순수 데이터 구조입니다.

| 필드 | 설명 |
|------|------|
| `id` | 고유 식별자 |
| `parentId` | 부모 노드 ID |
| `childrenIdList` | 자식 노드 ID 목록 |
| `unlockId` | 연결된 콘텐츠 Unlock ID |
| `isActive` | 활성 상태 |

> **설계 의도**: UI 로직과 상태 데이터를 분리하여 RedDot은 읽기 전용 구조로 동작하도록 설계했습니다.

### 3. RedDotManager

게임 내 RedDot 상태를 관리하는 중앙 관리자입니다.

- RedDot 트리 구성
- 상태 변경 처리 및 부모 노드 상태 전파
- Unlock 상태 검증
- 이벤트 기반 UI 갱신

---

## 트리 전파 구조

Leaf RedDot 상태 변경 시 **자신 → 부모 → 상위 부모** 순으로 상태가 전파됩니다.
부모 RedDot은 자식 중 하나라도 활성화 상태라면 활성 상태를 유지합니다.

이를 통해 개별 콘텐츠 상태만 변경해도 상위 메뉴 알림이 자동 갱신됩니다.

---

## Unlock 지연 처리

콘텐츠가 잠긴 상태에서 RedDot이 활성화되는 경우, 즉시 표시하지 않고 상태 변경을 대기시킵니다.

1. Lock 상태 감지
2. 활성 요청 상태 저장
3. Unlock 이벤트 발생 시 재적용

> 플레이어가 접근할 수 없는 콘텐츠에 알림이 표시되는 UX 혼란을 방지하기 위한 설계입니다.

---

## 데이터 기반 구성

RedDot 트리는 두 방식으로 생성됩니다.

1. **메타데이터 기반 생성** — 고정 콘텐츠 RedDot
2. **런타임 동적 생성** — 반복 구조 콘텐츠 대응, 데이터 작업량 감소 목적

---

## 상태 갱신 흐름

```
1. 게임 이벤트 발생
2. RedDotManager.SetActiveRedDot 호출
3. Unlock 상태 검사
4. Leaf 상태 변경
5. 부모 노드 재귀 전파
6. OnChangedRedDot 이벤트 발생
7. UI RedDot 갱신
```
